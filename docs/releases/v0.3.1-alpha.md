## Núcleo v0.3.1-alpha

Verifica lo que descargas antes de usarlo. El procedimiento está en
[docs/RELEASING.md](https://github.com/nucleoledger/nucleo/blob/v0.3.1-alpha/docs/RELEASING.md#verificar-una-descarga)

Los binarios no llevan clave privada detrás: la firma es keyless de Sigstore,

### Qué trae esta versión

Una versión de parche tras la revisión del cambio de passphrase de v0.3.0-alpha
(ADR-029), hecha por un modelo de IA el 2026-10-03:
[el informe](https://github.com/nucleoledger/nucleo/blob/v0.3.1-alpha/docs/revision-externa-modelo-20261003.md),
tal como lo escribió. No encontró ninguna forma de dejar un vault sin abrir. Sus tres
hallazgos están cerrados:

- **Una passphrase olvidada no es una passphrase robada.** `restore --new-passphrase`
  cambia la cerradura, no lo que hay dentro: la clave de datos y las claves de firma no
  cambian, y quien tuvo la passphrase y una copia del ledger pudo llevárselas. La CLI
  (`nucleo -h`, «PASSPHRASE OLVIDADA O ROBADA»), el tutorial y
  [OPERACION.md §3](https://github.com/nucleoledger/nucleo/blob/v0.3.1-alpha/docs/OPERACION.md)
  dicen ahora qué hacer en cada caso; si fue robada, un log nuevo y el viejo retirado
  ([enmienda de ADR-029](https://github.com/nucleoledger/nucleo/blob/v0.3.1-alpha/docs/adr/ADR-029-restore-fija-passphrase-nueva.md)).
- **Un `seal` ya desbloqueado cuando `restore` cambia la passphrase termina, y su bloque
  vale.** Se deja así, con un test que lo fija; por qué un bloqueo no protegería nada está
  en la enmienda.
- **La KEK, la clave de datos y la passphrase se borran de memoria** en cuanto dejan de
  hacer falta, hasta donde Go lo permite, y el límite está escrito.
- **El tutorial repite** que una copia del ledger de antes del cambio se sigue abriendo con
  las tarjetas viejas.

**Qué le cuesta a quien venga de v0.3.0-alpha: nada.** Ni formato, ni ledger, ni salida
`--json` cambian, y los SDK tampoco. El detalle, en el
[CHANGELOG de este tag](https://github.com/nucleoledger/nucleo/blob/v0.3.1-alpha/CHANGELOG.md#031-alpha--2026-10-07).

### El verificador para tus clientes

```bash
npm install @nucleoledger/verify@0.3.0-alpha.0
npm audit signatures    # "1 package has a verified attestation": lo publicó el CI de este repositorio
```

Sigue siendo 0.3.0-alpha.0: esta versión no cambia nada de lo que verifica.

### Verificar esta descarga

Con el bundle de Sigstore (`checksums.txt.sigstore.json`) o con `checksums.txt.sig` y
`checksums.txt.pem`, como en v0.3.0-alpha, y la identidad exacta de este tag. El tag
`v0.3.1-alpha` va firmado con SSH (`git tag -v v0.3.1-alpha`).

**PENDIENTE antes de publicar el borrador:** el sha256 completo del binario linux/amd64
publicado y el del recompilado desde el tag, y el resultado de verificar esta descarga con
las dos recetas.

### Estado, sin adornos

revisiones fueron adversariales y hechas por modelos de IA— y **nadie lo usa en
producción**. Para reportar una vulnerabilidad en privado: el botón *Report a
vulnerability* de la pestaña Security del repositorio, o security@nucleoledger.com
([SECURITY.md](https://github.com/nucleoledger/nucleo/blob/v0.3.1-alpha/SECURITY.md)).
